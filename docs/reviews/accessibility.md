# Accessibility review: Yawmy Care landing page (WCAG 2.2 AA)

Date: 2026-10-23. Scope: `/en/` and `/ar/`, whole page, dev server `http://localhost:4323`. Read-only audit (no `src/` edits).
Documented colour trade-offs in `docs/DECISIONS.md` (#1, #2, #3, #14) are not re-reported; their numbers were re-measured and are correct (white on `#5E7748` = 4.95:1, `#5E7748` on `surface-sec` = 4.82:1, `#E06950` on `surface-sec` = 3.22:1, field border = 3.48:1).

Method: axe-core 4.10.2 (wcag2a/aa, 21a/aa, 22aa, best-practice) per locale and again with menu + all FAQ rows open, and on the open dialog in its error state; own contrast sweep of every rendered text node (computed colours, SVG blob fills resolved through `elementsFromPoint`, 145-175 text elements per run) at 1440 / 768 / 375 / 320 in EN and AR; real key presses (Tab, Enter, Space, Arrows, Esc) in the browser; computed focus ring + adjacent-colour contrast for all 53 focusable elements; target-size, reflow (320), text-spacing (1.4.12) scripts; source read of Header, DemoModal, Button, Faq, Footer, Features, Pricing, Commitments, BaseLayout. Verdict: **PASS WITH ISSUES**. 0 blockers.

Line numbers are as of the audit and may have shifted (two QA engineers were editing responsive CSS).

## Dev-only / environment notes (not counted)

- Astro dev toolbar (`astro-dev-toolbar`) sits in the tab order and swallowed the first Tab after some interactions. Not in a production build.
- Dev server only: `Features.astro` `spaceSafe()` workaround for spaces in the path. Production URLs fine.
- Dialog cannot open without JS (stated in `DemoModal.astro` header comment). With JS off the Book a Demo links jump to `#demo` and nothing happens; FAQ rows without JS keep all answers visible but buttons still announce `aria-expanded="false"`. Acceptable for a JS-built page but worth a `<noscript>` contact line.

## Passes

Automated
- axe-core 4.10.2, EN + AR: 1 violation each (`color-contrast` on the decorative wordmark, finding 21), 43 rule passes each; EN also clean with the mobile menu open and all 13 FAQ rows open; dialog (open + error state) 0 violations, 21 passes.
- axe "incomplete" (80 EN / 40 AR contrast nodes, all "background could not be determined" over SVG blob fills or overlapping elements) was re-measured by hand: **0 failures** in 145-175 text elements per run at 1440, 768, 375, 320 (EN 1440/375, AR 1440/768/320). Lowest passing pairs: testimonial attribution `#B5503C` on `#FCF1E6` 4.52:1 (very thin margin, 14px bold, do not darken the fill any further), "Be The First Partner" 4.76:1, nav current link 4.82:1.

Structure and names
- `html lang` `en`/`ar`, `dir` `ltr`/`rtl`, locale-specific `<title>` and `<meta description>`, canonical + hreflang (en, ar, x-default) correct.
- Exactly one `h1` per locale; h1 > h2 > h3 with no skipped level and no empty heading; FAQ question buttons are inside `h3`; the decorative number circle is `aria-hidden` so the accessible name is the question only.
- Landmarks: `header` (banner), 2 `nav` with names ("Main navigation", footer nav), single `main#main`, `footer` (contentinfo). Skip link is the first Tab stop, visible on focus, target exists.
- Every control has a name in the page language: social links (EN+AR), logo link, language switch ("Switch language to Arabic" / "التبديل إلى اللغة الإنجليزية", `hreflang` set; visible variant carries `lang`), menu button, FAQ buttons, dialog close, all inputs via `<label for>`. No empty links or buttons.
- 9 anchor links all resolve (`#home #day #why #setup #security #commitments #pricing #founders #faq`) in order; scroll-spy keeps exactly one `aria-current="location"` (header + panel in sync), initial Home server-rendered.
- Mobile menu: `aria-expanded` + `aria-controls`, `display:none` when closed (hidden from AT and tab order), Esc closes and returns focus to the toggle, outside click and link click close, no JS = panel visible. Tab order toggle -> panel links is natural.
- FAQ: Space/Enter toggle, Arrow/Home/End navigation verified; collapsed answers use `visibility:hidden` (not reachable); height animation gated by `prefers-reduced-motion: no-preference`; `aria-controls` ids exist.
- Dialog: native `showModal` (page inert), `aria-labelledby` + `aria-describedby` that swap with state, initial focus on first field, focus loops submit -> close -> name (verified), Esc closes, focus returns to the opener (hero/header path verified), success/error headings take focus, honeypot is `aria-hidden` + `inert` + `tabindex=-1` + `autocomplete=off`, `autocomplete` tokens `name`/`organization`/`email` (1.3.5), per-field `aria-invalid` + `aria-describedby` errors in text (not colour only), error colour 5.0:1, field border 3.48:1, placeholders 7.65:1.
- Decorative images `alt=""` (feature/pricing/commitment illustrations, logo inside labelled link, secondary phone layers); informative images have alt, and **AR alts are translated** (12 of 12 checked); Latin brand wordmark and "English" link carry `lang="en"`, the AR badge `lang="ar"`.
- Lists/time: day timeline is an `ol` with a label, each slot has a `<time datetime>` inside `bdi`; numbers/attributions wrapped in `bdi` for bidi isolation; email field switches to `dir=ltr` once it has a value.
- Reading/focus order in RTL follows the DOM (header, top bar, footer all start at the inline start); no tabindex > 0; no keyboard traps.

Perceivable / operable
- Focus ring present and >= 3:1 on every other focusable element (52 of 53 checked, desktop): `#334722` rings 8.2-10.1:1 on cream/green, `#F8FAEE` rings 4.73:1 on the `#5E7748` bands, FAQ row 3px ring 10.1:1.
- Reflow at 320px: no horizontal scroll, no clipped controls (EN and AR); 1.4.12 text-spacing override at 320: no text clipped or overlapping (the day-card "clipping" reported by a naive script is the intentional cropped phone images, text is in flow).
- Targets: nothing under 24px; at 375 everything is >= 44 (social 40 + 4px pseudo hit area).
- No `position:fixed/sticky` chrome, so nothing can obscure focus (2.4.11); no hover-only or tooltip content; no `title` attributes; `meta viewport` allows zoom; no autoplay media other than the WebPs in finding 4; no seizure-risk flashing.
- `prefers-reduced-motion`: all transitions `motion-safe:`; no CSS animation or smooth scroll in `src/`.

## What automation could not cover (not done / needs a human)

- Real screen-reader passes (NVDA+Chrome, VoiceOver iOS/macOS, TalkBack), especially: dialog open/close announcements, live-region behaviour in findings 9-10, Arabic voice pronunciation of mixed Latin/Arabic strings.
- `prefers-reduced-motion: reduce` was not emulated live (tool cannot); verified by reading the `<source media>` markup and fetching all 14 still URLs.
- Windows forced-colors / high-contrast mode (SVG blob fills, pill buttons with no border) and Safari/Firefox focus-ring rendering.
- True 400% browser zoom on a desktop (320 CSS px was emulated) and landscape phones.
- Quality of the drafted Arabic copy and alt text (flagged `_review`), and whether the alt text for 12+ UI screenshots is the right level of detail.
- Native date/time inputs: format follows the browser locale (an Arabic page in an English browser shows `mm/dd/yyyy`); not a defect in the code, but test on real devices.
